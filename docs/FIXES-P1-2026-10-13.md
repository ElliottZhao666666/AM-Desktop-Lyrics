# P1 修复记录（2026-10-13）

本次对应复盘中的 01–07，以及用户明确要求的 15。前端只调整启动恢复、事件时序及时间传参，没有更改布局、主题编辑器或歌词渲染样式。

| 问题 | 修复 |
| --- | --- |
| 01 配置相互覆盖 | 设置与渠道统一使用受锁保护的 JSON 合并写入；同目录临时文件同步落盘后原子替换，保留 Token、渠道、窗口位置及未知字段；配置损坏时报错，避免覆盖原文件 |
| 启动偏移为 0 | 在创建 WebView 前恢复运行时偏移；首次 IPC 同样保证初始化；前端独立恢复设置/偏移，字体枚举失败不再阻断面板；回归覆盖 -1500ms 启动和继续提前为 -2000ms |
| 02 时间轴回跳 | 按 LastUpdatedTime 和 PlaybackRate 估算当前进度；处理 StartTime；重复原始位置不会每秒拉回插值位置，真实 seek 仍会校准 |
| 03/07 缓存身份不可靠 | 扫描只产生候选，必须查询/读取 lyricsId 对应的 Apple 歌曲元数据，核对歌名、歌手、版本、专辑、歌曲时长及 TTML 时长；时间新鲜度只作排序辅助 |
| 03 API 跟随错误缓存 | 本地缓存和 syllable-lyrics 共用同一份已核验 ID；缓存不可信就回退其他源；API 响应时长与核验缓存冲突时拒绝使用 |
| 04 切歌使用旧时长 | SMTC 事件仅入队，独立 WinRT 线程串行去抖和读取；新歌元数据前后校验，旧时间轴先置为未知，正确时长到达后补查；不在等待新元数据时给旧歌发送新进度 |
| 05 启动丢歌词 | 后端保存完整歌词/加载状态快照；前端监听就绪后恢复；媒体、进度、歌词都有曲目版本和消息版本，拒绝过期快照与 A→B→A 的旧结果 |
| 06 QQ 取错误第一项 | 使用各渠道共用评分器，可靠歌名/歌手是必要条件，版本和明显时长冲突直接拒绝；专辑与接近程度用于排序；最多尝试三个可信候选，没有可信候选就返回未找到 |
| 15 汉字“一”被拆分 | 只删除“一”的分隔匹配，其余原有符号保留 |

真实缓存还发现 `AP_歌曲ID-en` 等语言后缀，现已解析为数字歌曲 ID，避免将语言后缀作为 catalog songs ID。

新增 `lyrics/matching.rs` 为通用评分器，不依赖 QQ 数据格式；后续网易云只需将候选转换成 TrackIdentity 和时长即可复用。歌曲名支持繁简和标点归一化，歌手支持多歌手集合比较；不以歌手子串匹配代替身份匹配。

为防止旧版本已经写入的错误普通缓存继续生效，普通缓存增加匹配版本，旧的未核验普通缓存会重新获取；永久手动绑定保持有效。Apple 歌曲元数据另存为 `apple-song-metadata.json`，后续已有元数据时可以离线核验缓存。首次核验失败时不会猜测缓存身份，而是回退其他渠道。

必要联动还包括：API 总超时、扫描移入阻塞工作线程、切歌取消旧自动任务、请求失败发送终态、渠道保存后重取当前歌词、Token 默认值初始化一致、控制条使用实际媒体时间而非歌词偏移时间。未处理的 P2 项（主题恢复、自定义字体输入、两套 TTML 解析、固定双行/滚动等）继续保留在复盘清单中。
